01

the why

why i built it

I'm moving to a new city, and I wanted to leave my friends something more fun than a goodbye: a chat app where they can text "me" anytime. It's for friends who'd laugh at a bot that says "LOL" and "fr????" in all lowercase, and who know it's a bot. The hard part was making it actually sound like me instead of a polite assistant, without letting it make things up or overshare.

02

how it works

the guts

The app is a Godot 4.7 project written in C#. The whole UI is drawn in code: the pink gradient and twinkling sparkles, iMessage-style bubbles with curled tails, tapback badges, a typing indicator and a sidebar of saved chats. There are no image assets besides the app icon.

When a friend sends a message, the app runs Claude Code headless on their computer (claude -p) with my persona file as the system prompt and the recent chat as input. The model answers with a JSON array of one to three short texts, and the app shows them one at a time with a typing delay sized to each message. A text can also be a special command instead of a message:

  • REACT: ❤️ puts a tapback on the friend's last message.
  • GIF: happy dance searches GIPHY (G-rated) and sends the result.
  • NAME: Millie tells the app who it's talking to, so it can remember them. The friend never sees it.

When a friend sends a photo, it's copied alone into an empty temp folder and the model gets only the Read tool there, so it can react to what's actually in the picture without seeing anything else.

Chats are saved as JSON on the friend's computer and get a short lowercase title once the bot has replied, like Claude's sidebar.

Key decisions

  • Claude Code instead of an API key: each friend uses their own Claude login, so there's no key to ship or server to pay for. The tradeoff is that friends need Claude Code installed.
  • No tools, no MCP servers: the model runs with tools and MCP servers off, so it can only see the chat and the persona. Even if someone asks it to, it can't read files.
  • The personality is one Markdown file: persona.md holds the voice rules, real example texts, GIF etiquette and boundaries, so tuning the bot means editing text, not code.
  • Godot for a desktop app: it gave me a custom-looking window, smooth animation and a one-folder Windows build without a web stack. Godot has no GIF loader, so GIFs are decoded into frames with System.Drawing.
  • The friend texts first: new chats start empty, and the bot learns who it's talking to from the conversation instead of a sign-up screen.
03

the hard parts

where it fought back

Making it sound like me

Problem: The first replies sounded like a cheerful assistant ("easy peasy 😎"), which is not how I text.

What I tried: Describing my style in general terms ("casual, friendly") wasn't enough. The model filled the gaps with its own idea of casual.

Fix: I wrote the persona from my real messages: all lowercase, dropped apostrophes, "LOL" and "fr????", short bursts, almost no emoji, plus a handful of real texts as examples. Then I added specific bans for things I never do, like saying "hey", starting every question with "wait", or giving advice nobody asked for. It also asks way more than it tells, because that's how I actually talk to friends.

Catching what it gets wrong

Problem: One-off test messages looked fine, but longer chats showed problems: it made up details about my life, offered to "run over to your desk", and once leaked its own self-correction ("wait, that breaks my persona rule, let me fix it") into the chat.

What I tried: Testing by hand was too slow to cover enough situations.

Fix: I asked Claude to play out full conversations between the bot and a simulated friend (a coworker with a bug, someone sharing big news, someone asking if it's a bot...) and write them to a file I could read through. Each round showed something to tighten: rules against inventing facts or being somewhere in person, joking dodges for personal questions ("a very important project called answering my phone"), and parsing that keeps only the bot's final JSON array, so stray notes never show.

04

what i learned

notes to future me

  • Voice comes from specifics. Real example texts and a few hard "never do this" rules did more than any description of a personality.
  • Single test prompts hide problems. Playing out whole simulated conversations is what showed the made-up facts and leaked notes.
  • A bot that dodges with a joke feels more like a person than one that explains it's a bot. Leaning on "im a bot" made it feel less like me.
  • Shipping to friends who aren't developers is its own project: a one-click launch and a bundled runtime matter as much as the features.
